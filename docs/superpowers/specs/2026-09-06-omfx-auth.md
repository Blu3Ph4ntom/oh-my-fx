# omfx ChatGPT Authentication Reliability Specification

**Status:** Approved design for implementation.

## Goal

Make ChatGPT/Codex subscription login reliable on Windows and make every
failure identify the provider that actually failed, without replacing a
working credential.

## Current evidence

The browser currently receives 'invalid_authorize_request' before the local
callback is reached. src/core/auth/chatgpt_oauth.zig builds the expected PKCE
request, but hardcodes originator=fx. The current Codex login source uses its
protocol originator value instead of the product display name:

- https://raw.githubusercontent.com/openai/codex/main/codex-rs/login/src/server.rs
- https://raw.githubusercontent.com/openai/codex/main/codex-rs/login/src/auth/default_client.rs

The local failure mapper also has a separate Vercel branch. A ChatGPT failure
must never be rendered as a Vercel failure.

## Contract

### Authorization request

Keep the registered client ID, localhost ports, PKCE verifier, state, and
current connector scope. Use the recognized Codex protocol originator
codex_cli_rs in both the authorization query and Codex API request headers.
Do not use fx or omfx as the OpenAI protocol originator.

The generated query must contain:

~~~text
response_type=code
client_id=app_EMoamEEZ73f0CkXaXp7hrann
redirect_uri=http://localhost:<registered-port>/auth/callback
scope=openid profile email offline_access api.connectors.read api.connectors.invoke
code_challenge=<base64url-without-padding>
code_challenge_method=S256
id_token_add_organizations=true
codex_cli_simplified_flow=true
state=<base64url-without-padding>
originator=codex_cli_rs
~~~

### Callback and credential safety

- Keep the callback server alive until the browser callback or explicit
  cancellation completes.
- Reject a missing or mismatched state before exchanging a code.
- Keep the current credential on every login error, timeout, cancellation, or
  failed persistence operation.
- Do not print access tokens, refresh tokens, authorization codes, or PKCE
  verifiers in notices or debug traces.
- Preserve the existing fallback port behavior.

### User-visible errors

Map notices by credential source:

- .chatgpt_subscription: Codex sign-in ...
- .fx_login: Vercel sign-in ...
- .opencode_go_subscription: OpenCode Go ... when its key setup fails

An authorization rejection must include a short safe reason when one is
available, while retaining the unchanged-credential statement. Optional
upgrade polling must not overwrite or masquerade as an auth result.

## Verification

Focused Windows CI tests must prove the generated URL uses
originator=codex_cli_rs and never originator=fx, the header builder uses the
same protocol value, source-specific notices use the correct provider name,
and failed login leaves the existing credential unchanged. A real Windows
artifact must reach the browser-login screen, allow Escape cancellation, and
return to the prompt without leaving a callback listener or stale auth status
behind.
