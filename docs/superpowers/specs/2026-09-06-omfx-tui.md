# omfx Windows TUI Reliability Specification

**Status:** Approved design for implementation.

## Goal

Make the Windows terminal interaction contract deterministic: keys reach the
currently focused surface, every accepted action causes the correct state and
frame update, and closing a surface restores the terminal without flicker or
stale modes.

## Existing ownership boundaries

- src/ui/input/escape_parser.zig parses terminal escape sequences.
- src/ui/input/terminal_action_decoder.zig converts byte streams into semantic
  actions and raw composer bytes.
- src/ui/input/runtime.zig owns decoder state, timeout flushing, and terminal
  mode setup.
- src/core/app/app_input_runtime.zig applies semantic actions according to the
  active modal, picker, composer, or child-terminal owner.
- src/ui/render_engine/terminal_diff.zig commits frames and tracks the shadow
  terminal grid.
- src/ui/shell_runtime.zig owns terminal modes and alternate-screen ownership.

No second Windows-only input or rendering path may be introduced.

## Input contract

The decoder and app router must satisfy this matrix in the composer and every
surface that advertises the action:

| Input | Required result |
| --- | --- |
| printable UTF-8 | Insert at the cursor without losing adjacent text |
| Enter / carriage return | Submit the focused form or prompt; insert a newline only where the surface declares multiline input |
| Escape | Cancel or close the focused surface; a bare Escape emits once after its timeout |
| Up / Down | Move the focused selection or composer visual row |
| Left / Right | Move the focused cursor or selection |
| Home / End | Move to the documented line or draft boundary |
| Backspace / Delete | Delete the intended grapheme, word, or line range |
| Tab / Shift-Tab | Complete or cycle only in a surface that owns completion or focus traversal |
| Ctrl-C / Ctrl-L / Ctrl-O | Use the existing semantic shortcut contract and never leak raw bytes into a modal |
| bracketed paste | Insert one bounded paste transaction and settle the owner before the next key |
| resize | Recompute layout and repaint the visible grid without duplicating or erasing transcript rows |

For Windows native consoles, raw mode must disable line buffering, echo,
processed input, and Quick Edit while enabling virtual-terminal input, and it
must restore the exact previous mode on every exit path. UTF-8 output must be
configured before emitting the interactive banner.

## Focus and rendering contract

- The active owner handles an action exactly once.
- A replay byte from escape parsing is fed through the decoder once and cannot
  bypass the owner-selection rules.
- Closing a menu or modal clears its input state, releases mouse, paste, focus
  ownership, and requests the smallest frame that reflects the new state.
- Alternate-screen owners remain exclusive and restore the main grid, cursor,
  paste, mouse, focus, and keyboard modes before returning.
- A frame commit updates the shadow grid only after the terminal accepts the
  bytes. Partial writes force a safe repaint instead of pretending the frame
  was committed.
- Repeated idle frames produce no output bytes; state changes produce one
  bounded repaint rather than a full-screen erase loop.

## Verification

Add pure decoder and app-router regression tests for the matrix above, frame
commit tests for no-op and partial-write behavior, and Windows CI filters for
each changed owner. The exact Windows artifact must be exercised in a real
terminal for composer editing, provider/model menus, auth cancellation,
resize, and clean /quit; the process must exit without stderr noise or a
leftover child process.
