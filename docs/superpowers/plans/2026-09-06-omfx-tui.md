# omfx Windows TUI Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make Windows key input, focus routing, terminal restoration, and frame commits deterministic across the interactive TUI.

**Architecture:** Keep byte parsing in src/ui/input, semantic routing in
src/core/app/app_input_runtime.zig, terminal mode ownership in
src/ui/shell_runtime.zig, and frame correctness in src/ui/render_engine.
Every regression enters through the existing decoder and owner contract.

**Tech Stack:** Zig 0.16, std.Io, virtual terminal engine, FX_RECORD replay,
GitHub Actions Windows-latest, and a real Windows terminal.

**Spec:** docs/superpowers/specs/2026-09-06-omfx-tui.md

## Global Constraints

- Do not run local Zig builds or tests; focused unit filters run on Windows Actions.
- Use zig fmt locally only for touched Zig files.
- Do not add a general alternate-screen path or bypass permission/focus ownership.
- Do not duplicate key handling in a Windows-only branch.
- Keep frame output bounded and preserve shadow-grid commit semantics.
- Commit each independently testable task.
