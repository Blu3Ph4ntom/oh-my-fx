# omfx ChatGPT Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Repair the ChatGPT subscription login request and make auth failures provider-accurate on Windows.

**Architecture:** Keep PKCE, state validation, localhost callback ownership, and
credential persistence in src/core/auth. Keep provider-specific notices in
src/core/app/app_auth_runtime.zig. Use the registered Codex protocol identity
only on the OpenAI auth/API wire; the public identity is supplied by the brand
plan.

**Tech Stack:** Zig 0.16, std.Io, existing OAuth transport, Windows-latest
GitHub Actions, downloaded Windows artifact.

**Spec:** docs/superpowers/specs/2026-09-06-omfx-auth.md

## Global Constraints

- Do not run zig build, zig build test, or zig test locally; focused checks run on Windows Actions.
- Use zig fmt locally only for touched Zig files; CI runs zig fmt --check src/.
- Keep the current credential unchanged on every failed login path.
- Do not put secrets, authorization codes, verifiers, or tokens in notices or traces.
- Use codex_cli_rs for the OpenAI protocol originator; never use fx or omfx there.
- Commit each independently testable task with a small imperative message.
